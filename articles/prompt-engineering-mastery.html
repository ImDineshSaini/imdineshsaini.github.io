I spent 3 hours trying to get GPT-4 to extract structured data from banking documents. The results were inconsistent and full of hallucinations. It was frustrating.

Then I learned about few-shot prompting (giving the LLM a few examples before the real task). Fifteen minutes later, it worked perfectly.

Prompt engineering is not magic. It is a craft you can learn. After building dozens of LLM-powered features in production, I have found the patterns that work reliably.

Why Prompt Engineering Matters

LLMs are powerful but unpredictable. The same prompt can give you very different results each time:

  • Perfect results (80% of the time)
  • Almost correct (15% of the time)
  • Complete nonsense (5% of the time)

In production, you need 99.9% reliability. You get there by engineering prompts the same way you engineer code.

Pattern 1: Zero-Shot vs Few-Shot vs Many-Shot

Zero-shot (no examples):

Extract the customer name from this email.

This works for simple tasks. It fails for anything nuanced.

Few-shot (2-5 examples):

Prompt — Few-shot name extraction 
Extract the customer name from these emails.

Example 1:
Email: "Hi, this is John Smith from Acme Corp."
Name: John Smith

Example 2:
Email: "Jane Doe here, reaching out about..."
Name: Jane Doe

Now extract from:
Email: "This is Michael Chen writing to inquire..."
Name:

This works much better. Few-shot is the sweet spot for most tasks.

Many-shot (10+ examples):

Use many-shot for edge cases and complex classification. It costs more because it uses more tokens (the units LLMs use to measure text length).

Our rule: Start with zero-shot. If accuracy drops below 95%, add 3-5 examples.

Pattern 2: Chain-of-Thought Reasoning

For complex tasks, ask the LLM to reason step by step. This technique is called chain-of-thought (asking the LLM to reason step by step). It dramatically improves accuracy.

Without chain-of-thought:

Is this transaction fraudulent?
Transaction: $5000 to "Luxury Goods Inc" from account with $200 balance.

The LLM might guess. That makes it unreliable.

With chain-of-thought:

Prompt — Chain-of-thought fraud analysis 
Analyze if this transaction is fraudulent. Think step by step:

1. Check account balance vs transaction amount
2. Look for unusual merchant patterns
3. Consider transaction velocity
4. Make final determination

Transaction: $5000 to "Luxury Goods Inc" from account with $200 balance.

Analysis:

The LLM reasons through each step. This leads to much better accuracy.

Pro tip: Chain-of-thought works even better when you combine it with few-shot examples of reasoning.

Pattern 3: Structured Output with JSON Mode

Free-form text is hard to parse in code. Use JSON mode when you need structured data back from the LLM.

Unreliable prompt:

Extract the name, email, and phone from this text.

The LLM might return: "The name is John, email is john@example.com and phone is 555-1234." Now you need regex to parse this. That approach is fragile.

Reliable prompt (JSON mode):

Prompt — JSON extraction 
Extract contact information and return as JSON.

Required fields:
- name (string)
- email (string or null)
- phone (string or null)

Text: "Contact John Smith at john@example.com or call 555-1234"

JSON:

The LLM returns clean JSON:

{
  "name": "John Smith",
  "email": "john@example.com",
  "phone": "555-1234"
}

This is easy to parse, type-safe, and needs no regex.

Using OpenAI's JSON mode:

const response = await openai.chat.completions.create({
  model: "gpt-4",
  messages: [{ role: "user", content: prompt }],
  response_format: { type: "json_object" }
});

Pattern 4: System Prompts for Consistent Behavior

System prompts define how the LLM behaves. They set constraints, tone, and rules that apply to every response.

Prompt — Banking compliance system prompt 
System: You are a banking compliance assistant. You:
- Always cite regulatory sources (e.g., "Per FINRA Rule 3210...")
- Never make up information
- If unsure, respond "I need more information to answer this"
- Use formal, professional language

User: What are the reporting requirements for suspicious transactions?

This dramatically improves consistency. Every response follows the same rules and tone.

Pattern 5: Temperature and Top-P

Temperature (a setting that controls how random the output is) lets you tune the LLM's creativity. Here is when to use each level:

  • Temperature 0: Deterministic. Same output every time. Best for data extraction.
  • Temperature 0.7: Balanced creativity. Good for content generation.
  • Temperature 1.5: Very creative and unpredictable. Good for brainstorming.
JavaScript — Temperature control examples 
// Reliable extraction (temperature 0)
const extract = await openai.chat.completions.create({
  model: "gpt-4",
  messages: [{ role: "user", content: extractionPrompt }],
  temperature: 0
});

// Creative writing (temperature 0.8)
const creative = await openai.chat.completions.create({
  model: "gpt-4",
  messages: [{ role: "user", content: writingPrompt }],
  temperature: 0.8
});

Pattern 6: Prompt Chaining

Break complex tasks into steps. Feed the output of step 1 into step 2. This gives you control at each stage and improves accuracy.

Example: Document classification + summarization

JavaScript — Prompt chaining example 
// Step 1: Classify
const classification = await llm.complete({
  prompt: "Classify this document: legal, financial, or technical.\n\n" + doc
});

// Step 2: Summarize (with classification context)
const summary = await llm.complete({
  prompt: `Summarize this ${classification} document in 3 bullet points.\n\n` + doc
});

Each step is simple and testable. The chain as a whole handles complex tasks reliably.

Real-World Example: KYC Document Extraction

We built a system to extract data from KYC documents like passports and utility bills.

Version 1 (naive):

Extract name, address, and date of birth from this document.

Accuracy: 60%. The LLM hallucinated values for missing fields.

Version 2 (few-shot + JSON + constraints):

Prompt — KYC extraction with few-shot + JSON 
System: You extract personal information from identity documents.
Rules:
- Only extract information explicitly present
- Return null for missing fields
- Never guess or infer

Examples:
[3 examples with edge cases]

Extract from this document and return JSON:
{
  "name": string or null,
  "address": string or null,
  "date_of_birth": string or null (YYYY-MM-DD format),
  "document_type": string,
  "confidence": number (0-1)
}

Document: [OCR text]

Accuracy: 96%. This version is production-ready. The key improvements were adding examples, requiring JSON, and telling the LLM to never guess.

Try It Yourself — Document Extraction
You extract personal information from identity documents.

Rules:
- Only extract information explicitly present in the text
- Return null for any missing fields
- Never guess or infer information
- Include a confidence score (0-1)

Return JSON:
{
  "name": "string or null",
  "address": "string or null",
  "date_of_birth": "YYYY-MM-DD or null",
  "document_type": "string",
  "confidence": 0.0
}

Try this with any document text. The confidence score helps you decide when to trust the output.

Testing and Versioning Prompts

Prompts are code. You should treat them like code. Version them, test them, and track changes.

1. Version control prompts

TypeScript — Prompt version control 
// prompts/kyc-extraction/v2.ts
export const KYC_EXTRACTION_PROMPT = `
Extract personal information from identity documents...
[full prompt]
`;

// Version history in git
// v1: Basic extraction (60% accuracy)
// v2: Few-shot + JSON (96% accuracy)

2. Create test datasets

JavaScript — Prompt test dataset 
const testCases = [
  { input: "passport with all fields", expected: {...} },
  { input: "utility bill missing address", expected: {...} },
  { input: "low quality scan", expected: {...} }
];

testCases.forEach(test => {
  const result = extractKYC(test.input);
  assert.deepEqual(result, test.expected);
});

3. A/B test prompts in production

JavaScript — A/B testing prompts 
const variant = Math.random() < 0.5 ? 'v1' : 'v2';
const result = await extractKYC(document, variant);

analytics.track('prompt_performance', {
  variant,
  accuracy: result.confidence,
  latency: result.latency
});

Common Mistakes to Avoid

  • Vague instructions: "Summarize this" is too broad. Say "Summarize in 3 bullet points, focus on financial impact" instead.
  • No examples for edge cases: Show the LLM what to do when data is missing or unclear.
  • Ignoring hallucinations: Always validate LLM outputs, especially for critical data.
  • Not using JSON mode: Parsing free-form text with regex is fragile. Use structured output.
  • Wrong temperature: Use 0 for extraction, 0.7 or higher for generation.
  • Long prompts without structure: Use headings, bullet points, and clear sections.

Advanced: RAG Prompts

RAG stands for Retrieval-Augmented Generation. It means you fetch relevant documents first, then include them in the prompt as context. This grounds the LLM's answers in real data.

Prompt — RAG with context grounding 
System: Answer questions using only the provided context.
If the answer isn't in the context, say "I don't have enough information."

Context:
[Retrieved chunks from vector DB]

Question: What are the KYC requirements for corporate accounts?

Answer:

Key insight: Tell the LLM explicitly to use only the provided context. Without this instruction, it will hallucinate answers from its training data.

Monitoring Prompt Performance

Track these metrics for every prompt in production:

  • Accuracy: Percentage of correct outputs. You need a labeled test set for this.
  • Consistency: Run the same prompt 10 times and measure how much the output varies.
  • Latency: Time to generate a response. Track p50, p95, and p99.
  • Cost: Tokens used per request, both input and output.
  • Failure rate: Percentage of requests that error out or time out.

We use Langfuse for prompt observability and experimentation. It tracks all of these metrics in one place.

Key Takeaways

  1. Few-shot beats zero-shot: Add 3-5 examples for a 20-30% accuracy boost.
  2. Use JSON mode for structured data: It eliminates parsing errors completely.
  3. Chain-of-thought for reasoning: "Think step by step" improves complex tasks.
  4. System prompts set behavior: Define constraints and personality upfront.
  5. Temperature 0 for extraction: Use deterministic outputs when you need reliability.
  6. Version control prompts: Treat prompts like code. Test every change.
  7. Monitor everything: Track accuracy, latency, cost, and consistency.
