Prompt Engineering Mastery: Getting LLMs to Do What You Want

I spent 3 hours trying to get GPT-4 to extract structured data from banking documents. The results were inconsistent, hallucinatory, and frustrating.

Then I learned about few-shot prompting. 15 minutes later, it worked perfectly.

Prompt engineering isn't magic—it's a craft. After building dozens of LLM-powered features in production, I've learned the patterns that actually work.

Why Prompt Engineering Matters

LLMs are powerful but unpredictable. The same prompt can give you:

  • Perfect results (80% of the time)
  • Almost correct (15% of the time)
  • Complete nonsense (5% of the time)

In production, you need 99.9% reliability. That requires engineering prompts like you engineer code.

Pattern 1: Zero-Shot vs Few-Shot vs Many-Shot

Zero-shot (no examples):

Extract the customer name from this email.

Works for simple tasks. Fails for nuanced ones.

Few-shot (2-5 examples):

Extract the customer name from these emails.

Example 1:
Email: "Hi, this is John Smith from Acme Corp."
Name: John Smith

Example 2:
Email: "Jane Doe here, reaching out about..."
Name: Jane Doe

Now extract from:
Email: "This is Michael Chen writing to inquire..."
Name:

Works significantly better. This is the sweet spot for most tasks.

Many-shot (10+ examples):

For edge cases and complex classification. Expensive (uses more tokens).

Our rule: Start with zero-shot. If accuracy < 95%, add 3-5 examples.

Pattern 2: Chain-of-Thought (CoT) Reasoning

For complex tasks, ask the LLM to "think step by step."

Without CoT:

Is this transaction fraudulent?
Transaction: $5000 to "Luxury Goods Inc" from account with $200 balance.

LLM might guess. Unreliable.

With CoT:

Analyze if this transaction is fraudulent. Think step by step:

1. Check account balance vs transaction amount
2. Look for unusual merchant patterns
3. Consider transaction velocity
4. Make final determination

Transaction: $5000 to "Luxury Goods Inc" from account with $200 balance.

Analysis:

LLM will reason through each step, leading to better accuracy.

Pro tip: CoT works even better with few-shot examples of reasoning.

Pattern 3: Structured Output with JSON Mode

Free-form text is hard to parse. Use JSON mode for structured data.

Unreliable prompt:

Extract the name, email, and phone from this text.

LLM might return: "The name is John, email is john@example.com and phone is 555-1234"

Now you need to parse this with regex. Fragile.

Reliable prompt (JSON mode):

Extract contact information and return as JSON.

Required fields:
- name (string)
- email (string or null)
- phone (string or null)

Text: "Contact John Smith at john@example.com or call 555-1234"

JSON:

LLM returns:

{
  "name": "John Smith",
  "email": "john@example.com",
  "phone": "555-1234"
}

Easy to parse, type-safe, no regex needed.

Using OpenAI's JSON mode:

const response = await openai.chat.completions.create({
  model: "gpt-4",
  messages: [{ role: "user", content: prompt }],
  response_format: { type: "json_object" }
});

Pattern 4: System Prompts for Consistent Behavior

System prompts set the LLM's "personality" and constraints.

System: You are a banking compliance assistant. You:
- Always cite regulatory sources (e.g., "Per FINRA Rule 3210...")
- Never make up information
- If unsure, respond "I need more information to answer this"
- Use formal, professional language

User: What are the reporting requirements for suspicious transactions?

This dramatically improves consistency across requests.

Pattern 5: Temperature & Top-P for Control

Control randomness with temperature:

  • Temperature 0: Deterministic, same output every time (good for extraction)
  • Temperature 0.7: Balanced creativity (good for content generation)
  • Temperature 1.5: Very creative, unpredictable (good for brainstorming)
// Reliable extraction (temperature 0)
const extract = await openai.chat.completions.create({
  model: "gpt-4",
  messages: [{ role: "user", content: extractionPrompt }],
  temperature: 0
});

// Creative writing (temperature 0.8)
const creative = await openai.chat.completions.create({
  model: "gpt-4",
  messages: [{ role: "user", content: writingPrompt }],
  temperature: 0.8
});

Pattern 6: Prompt Chaining for Complex Tasks

Break complex tasks into steps. Output of step 1 → input of step 2.

Example: Document classification + summarization

// Step 1: Classify
const classification = await llm.complete({
  prompt: "Classify this document: legal, financial, or technical.\n\n" + doc
});

// Step 2: Summarize (with classification context)
const summary = await llm.complete({
  prompt: `Summarize this ${classification} document in 3 bullet points.\n\n` + doc
});

Chaining gives you control at each step and improves accuracy.

Real-World Example: KYC Document Extraction

We built a system to extract data from KYC documents (passports, utility bills, etc.).

Version 1 (naive):

Extract name, address, and date of birth from this document.

Accuracy: 60%. Hallucinated missing fields.

Version 2 (few-shot + JSON + constraints):

System: You extract personal information from identity documents.
Rules:
- Only extract information explicitly present
- Return null for missing fields
- Never guess or infer

Examples:
[3 examples with edge cases]

Extract from this document and return JSON:
{
  "name": string or null,
  "address": string or null,
  "date_of_birth": string or null (YYYY-MM-DD format),
  "document_type": string,
  "confidence": number (0-1)
}

Document: [OCR text]

Accuracy: 96%. Production-ready.

Testing & Versioning Prompts

Prompts are code. Treat them like code:

1. Version control prompts

// prompts/kyc-extraction/v2.ts
export const KYC_EXTRACTION_PROMPT = `
Extract personal information from identity documents...
[full prompt]
`;

// Version history in git
// v1: Basic extraction (60% accuracy)
// v2: Few-shot + JSON (96% accuracy)

2. Create test datasets

const testCases = [
  { input: "passport with all fields", expected: {...} },
  { input: "utility bill missing address", expected: {...} },
  { input: "low quality scan", expected: {...} }
];

testCases.forEach(test => {
  const result = extractKYC(test.input);
  assert.deepEqual(result, test.expected);
});

3. A/B test prompts in production

const variant = Math.random() < 0.5 ? 'v1' : 'v2';
const result = await extractKYC(document, variant);

analytics.track('prompt_performance', {
  variant,
  accuracy: result.confidence,
  latency: result.latency
});

Common Mistakes to Avoid

  • Vague instructions: "Summarize this" → "Summarize in 3 bullet points, focus on financial impact"
  • No examples for edge cases: Include examples of what to do when data is missing/unclear
  • Ignoring hallucinations: Always validate LLM outputs, especially for critical data
  • Not using JSON mode: Parsing free-form text is fragile
  • Wrong temperature: Use 0 for extraction, 0.7+ for generation
  • Long prompts without structure: Use headings, bullet points, clear sections

Advanced: Retrieval-Augmented Generation (RAG) Prompts

When using RAG, your prompt includes context from a vector database:

System: Answer questions using only the provided context.
If the answer isn't in the context, say "I don't have enough information."

Context:
[Retrieved chunks from vector DB]

Question: What are the KYC requirements for corporate accounts?

Answer:

Key insight: Explicitly tell the LLM to use only provided context. Otherwise it hallucinates.

Monitoring Prompt Performance

Track these metrics:

  • Accuracy: % of correct outputs (requires labeled test set)
  • Consistency: Run same prompt 10x, measure variance
  • Latency: Time to generate (p50, p95, p99)
  • Cost: Tokens used per request (input + output)
  • Failure rate: % of requests that error or timeout

We use Langfuse for prompt observability and experimentation.

Key Takeaways

  1. Few-shot beats zero-shot: Add 3-5 examples for 20-30% accuracy boost
  2. Use JSON mode for structured data: Eliminates parsing errors
  3. Chain-of-thought for reasoning: "Think step by step" improves complex tasks
  4. System prompts set behavior: Define constraints and personality upfront
  5. Temperature 0 for extraction: Deterministic outputs when you need reliability
  6. Version control prompts: Treat prompts like code, test changes
  7. Monitor everything: Accuracy, latency, cost, consistency
